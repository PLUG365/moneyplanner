# 履歴一覧は既定で当日までを表示する（2026-08-07）

## 背景

履歴一覧は日付降順のカーソルページングで読む（`hooks/usePaginatedTransactions.ts`）。
給料日・引き落とし日などを先の日付で登録すると、その予定が一覧の先頭を占め続け、
初期表示で直近の記録が見えなくなる（Issue #13）。

## 決定

履歴一覧に出す日付の上限を既定で当日にする。判定は純関数
`lib/historyFutureVisibility.ts` の `resolveHistoryDateCutoff` / `filterTransactionsUpToDate`。

- 設定タブの「未来の記録を表示」をオンにすると上限を外す
- 検索で終了日を明示指定した場合は上限を足さない。指定した期間を出しているのに空になる方が
  分かりにくいため、ユーザーの明示指定を優先する
- 上限で隠れた件数は、一覧が空のときだけ空表示に添えて知らせる

設定は端末ローカル（`lib/historyDisplayPreference.ts`、テーマ設定と同じ
`expo-file-system/legacy` のJSONファイル）に保存する。世帯で共有すると、同居人の見え方まで
勝手に変わってしまうため。

## カレンダービューに適用しない理由

カレンダーは月を選ぶ操作自体が期間指定にあたる。上限を適用すると、翌月へ送ったときに
カレンダーが必ず空になり、月送りが壊れて見える。初期表示の問題は一覧側で起きているため、
適用範囲を一覧に限った。

## 採用しなかった案: 検索条件の終了日を既定で当日にする

Issue 本文で挙がっていた案だが、現在の実装では**検索条件が1つでも入っていると
全件読み（`readAll`）に切り替わる**（`lib/paginatedTransactionsMode.ts` /
`lib/historySearchCriteria.ts`）。終了日を既定値にすると常に全件読みになり、
「大量履歴で全件購読・全件描画を避ける」という既存方針に反する読み取り量になる。

上限は表示側のフィルタとして持たせ、読み取り経路は従来どおりページングのままにした。

## 影響

- Firestore の読み取りクエリは変更なし（表示側フィルタのみ）。
- 合計表示（`buildHistorySearchTotals`）は上限適用後の配列から出すため、一覧と合計がずれない。
- 実機確認は、翌日以降の日付で記録して履歴一覧に出ないこと、設定をオンにすると出ること、
  検索で終了日を先の日付にすると出ることを見る。
